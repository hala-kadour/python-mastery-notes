## 📖 The Full Explanation

### 1. The Windows Python problem (read this first)

Windows has a **long history of Python installation pain**. Here's what's actually going on, so you avoid every trap:

**Trap 1 — The Microsoft Store fake Python.**  
When you type `python` in PowerShell on a fresh Windows 10/11, Windows may open the **Microsoft Store** instead of running Python. This is because Windows ships with a fake `python.exe` stub in `WindowsApps/` that redirects to the Store. **Never install Python from the Microsoft Store** — it creates a sandboxed installation that's hard to find, hard to manage, and breaks `pip install` in confusing ways.

**Trap 2 — PATH.**  
`PATH` is an environment variable that tells Windows *where to look for executable files*. If Python isn't on PATH, `python` won't work even if Python is installed. The official installer has a checkbox: **"Add python.exe to PATH"** — **you must check it**.

**Trap 3 — Multiple Pythons.**  
Windows accumulates Python installations like lint. After a few months you can have: Microsoft Store Python, python.org Python, Anaconda Python, and a Python bundled with some app. They fight. `python` might run the wrong one. **`uv` solves this entirely** — it manages Python versions for you, isolated from the system.

**Our approach:** We'll install **one** clean Python from python.org, then install `uv` to manage everything else. No Anaconda, no Store Python, no chaos.

### 2. Install Python 3.12+ from python.org

**Step 1 — Download.**  
Go to **https://www.python.org/downloads/windows/** and download the latest **Python 3.12.x** (or 3.13.x if available) **Windows installer (64-bit)**.

> ⚠️ **Do NOT download the "Windows embeddable package"** — that's for embedding Python in other apps, not for development.  
> ⚠️ **Do NOT use the Microsoft Store version.**  
> ✅ Download **"Windows installer (64-bit)"**.

**Step 2 — Run the installer.**  
- ✅ **Check "Add python.exe to PATH"** at the bottom of the first screen — this is the most important checkbox in this entire lesson
- Click **"Install Now"** (or "Customize installation" if you want to change the install directory — the default is fine)
- Optionally check **"Install for all users"** if you want it system-wide (needs admin)

**Step 3 — Verify.**

Open **PowerShell** (Win → type "PowerShell" → Enter) and run:

```powershell
python --version
```

Expected output:

```
Python 3.12.x
```

If you see that — ✅ you're done.

If you see "Python was not found" or the Microsoft Store opens:

· The PATH checkbox wasn't checked, OR
· You installed the Store version

Fix: Uninstall whatever you installed (Settings → Apps → Python → Uninstall), redownload from python.org, and check the PATH box this time.

Also check pip (Python's package installer — we'll barely use it once uv is installed, but it should exist):

```powershell
pip --version
```

Expected:

```
pip 24.x from C:\Users\...\Python312\Lib\site-packages\pip (python 3.12)
```

3. The python vs py vs python3 confusion on Windows

This trips up every Windows Python beginner:

Command What it is When to use
python The default Python on PATH ✅ Use this — works after our install
py Python Launcher for Windows — a separate tool that finds the "best" Python ⚠️ Works even with multiple Pythons; useful for version switching
python3 On Windows, usually does not exist (it's a Linux/macOS convention) ❌ Don't rely on it on Windows

On Linux/macOS: python might point to Python 2 (legacy) and python3 is the real one.
On Windows: after our install, python is Python 3. python3 won't work by default.

Trick: Try py --list in PowerShell — it lists all installed Pythons:

```powershell
py --list
```

```
 -V:3.12 *        Python 3.12 (64-bit)
```

We'll use python throughout the course. If you ever see tutorials use python3, mentally translate to python on Windows.

4. Install uv — the modern Python toolchain

What is uv?
uv is a Rust-based Python toolchain built by Astral. It replaces a whole stack of tools:

Old tool What it did uv equivalent
pip Install packages uv pip install (or uv add in projects)
venv Create virtual environments uv venv
pip-tools Lock dependencies uv lock
pipx Install CLI tools globally uv tool install
pyenv / pyenv-win Manage Python versions uv python install
poetry / hatch Project + dependency management uv init, uv add, uv sync

Why uv?

· 10–100x faster than pip (written in Rust)
· One tool for everything — fewer moving parts
· Reproducible — lock files are first-class
· Python version management — downloads and installs Python versions on demand
· Industry standard now — adopted by major projects in 2024–2025

Install uv on Windows — open PowerShell and run:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

That's it. uv installs to %USERPROFILE%\.local\bin\uv.exe and adds itself to PATH.

Verify:

```powershell
uv --version
```

Expected:

```
uv 0.5.x (or newer)
```

If uv is not found: close and reopen PowerShell (PATH changes need a new shell session).

5. Install VS Code (the editor)

Why VS Code? It's the de-facto standard for Python development, free, cross-platform, has excellent Python support, and its Jupyter extension is best-in-class.

Step 1 — Download.
Go to https://code.visualstudio.com/ and download the Windows installer. Run it. Default options are fine. ✅ Check "Add to PATH" and "Open with Code" options.

Step 2 — Install extensions.
Open VS Code, press Ctrl+Shift+X to open the Extensions panel, and install:

Extension ID Why
Python ms-python.python Language support, debugging, IntelliSense
Pylance ms-python.vscode-pylance Fast type checker and autocomplete (usually installed with Python ext)
Jupyter ms-toolsai.jupyter Notebook support inside VS Code
Ruff charliermarsh.ruff Ultra-fast linter + formatter (we'll use it in Module 8)
Even Better TOML tamasfe.even-better-toml Syntax highlight for pyproject.toml

Optional but recommended:

Extension ID Why
GitLens eamodio.gitlens Git superpowers inside VS Code
Error Lens usernamehw.errorlens Show errors inline
Indent Rainbow oderwat.indent-rainbow Python cares about indentation — this helps

Step 3 — Configure VS Code for Python.
Open VS Code settings (Ctrl+,), search for these and set them:

· "Editor: Format On Save" → ✅ check
· "Python › Analysis: Type Checking Mode" → set to basic (we'll upgrade to strict in Module 8)
· "Files: Auto Save" → set to onFocusChange (saves when you switch away)

Trick: Press Ctrl+Shift+P to open the Command Palette — it's how you do everything in VS Code. Type Python: Select Interpreter to choose which Python VS Code uses.

6. Run Python three ways

You now have three workflows. Learn all three — each has its place.

Way 1 — The REPL (interactive)

The REPL stands for Read–Eval–Print Loop. It's a live Python shell: you type code, it runs immediately. Perfect for testing small ideas.

Open it: In PowerShell, run:

```powershell
python
```

You'll see:

```
Python 3.12.x (main, ...) [MSC v.1938 64 bit (AMD64)] on win32
Type "help", "copyright", "credits" or "license" for more information.
>>>
```

The >>> is the prompt. Try:

```python
>>> 2 + 2
4
>>> import this
The Zen of Python, by Tim Peters
...
>>> exit()
```

Exit the REPL: type exit() or press Ctrl+Z then Enter.

Trick: Use ↑ and ↓ to scroll through command history. Use Ctrl+L to clear the screen.

Way 2 — A script file (.py)

Create a file hello.py anywhere (I suggest making a python-playground/ folder):

```python
# hello.py
name = input("What's your name? ")
print(f"Hello, {name}! Welcome to Python.")
```

Run it from PowerShell in that folder:

```powershell
python hello.py
```

Output:

```
What's your name? Sara
Hello, Sara! Welcome to Python.
```

Way 3 — A Jupyter notebook (.ipynb)

A Jupyter notebook is a document that mixes code cells, output, and markdown text. It's the standard for data science and AI.

In VS Code:

1. Create a file playground.ipynb
2. VS Code asks you to select a kernel — choose the Python interpreter we just installed
3. Click "Run" on a code cell, or press Shift+Enter

Try:

```python
# Cell 1
import sys
print(sys.version)
```

```python
# Cell 2
import platform
print(platform.python_implementation())
```

```python
# Cell 3 — markdown-style output
# Python is running inside a notebook 🎉
```

When to use which:

Way Best for
REPL Quick experiments, testing syntax, debugging 1-liners
Script Real programs, automation, anything you'll version control
Notebook Data exploration, ML experiments, teaching, reports

Professional tip: Use the REPL for thought, scripts for tools, notebooks for stories.

8. Fixing the "PowerShell can't run scripts" issue (if it happens)

Windows PowerShell has an execution policy that blocks running .ps1 scripts by default. If you see:

```
cannot be loaded because running scripts is disabled on this system
```

Run this once (in PowerShell):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Confirm with Y when prompted. This allows locally-written scripts to run (which uv needs for some operations) while still blocking unsigned downloads.

⚠️ Gotchas & Traps

1. Installing Python from the Microsoft Store.
      → Don't. It sandboxes Python, pip installs go to weird places, and debugging install issues becomes a nightmare. Use python.org only.
2. Forgetting the PATH checkbox in the installer.
      → If python isn't recognized after install, this is almost always why. Uninstall, redownload, reinstall with the box checked. Or use uv which avoids the issue entirely.
3. Typing python3 on Windows.
      → On Windows, python is Python 3. python3 usually doesn't exist. Use python.
4. Using the Windows py launcher and getting confused.
      → py is a separate tool from python. It picks the "best" Python. In this course we use python directly. If you see a tutorial using py, it's usually just for multi-version setups — not something we need.
5. Not restarting PowerShell after installing uv.
      → uv adds itself to PATH, but the current shell doesn't see it until restarted. Close and reopen PowerShell.
6. Running scripts from the wrong directory.
      → python hello.py only works if hello.py is in the current directory (or you give a full path). cd to the right folder first. Use pwd to check where you are, ls to see files.
7. Editing .py files in Notepad.
      → Notepad saves as UTF-8 with BOM sometimes, and doesn't handle indentation visibly. Use VS Code — it's installed now.
8. Confusing REPL with script mode.
      → In the REPL, >>> means you're in interactive mode. To run a .py file, you must exit the REPL first (exit()), then run python file.py in PowerShell. If you type python hello.py inside the REPL, you'll get a SyntaxError.
9. Opening VS Code but not selecting an interpreter.
      → VS Code needs to know which Python to use. Ctrl+Shift+P → "Python: Select Interpreter" → choose the 3.12 one. Otherwise IntelliSense and Run button use the wrong Python.
10. Forgetting to save before running.
        → In VS Code, an unsaved file has a white dot on the tab. Ctrl+S saves. The Python extension can be configured to always run the saved version (default), so unsaved changes are silently ignored. This has confused every beginner ever.
